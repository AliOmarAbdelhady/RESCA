# RescueVision V4 experiment registry

This registry records the V4 implementation gates separately from model scores. A
passing local test does not imply a Kaggle run, an artifact transfer, or useful
generalization. The laptop remains source-only; the first remote xBD audit, a bounded
DINOv3 ViT-L D0 smoke, and one full-coverage D0 epoch have completed on Kaggle.
The resumable two-epoch smoke also completed on Kaggle. This is still an
implementation/coverage gate, not a benchmark accuracy result or production
training run. **27 October review:** the training rasterizer reads GeoJSON
`geometry` objects, whereas the mounted xBD audit shows WKT features. The
training results and checkpoints are invalid for supervised evaluation until
the label path is corrected and verified against the actual mounted data.
The earlier K2 inventory did not validate rasterized targets or split integrity.

**Current execution policy:** the laptop is source-only. Do not run tests, the
CLI, notebooks, downloads or training on its CPU/GPU. K2 onward must execute in
an authenticated Kaggle/Colab runtime and return verifiable artifacts.

## Current V4 interfaces

- `rescuevision_ai.v4.contracts`: `ExperimentConfig` and immutable `SampleRecord`.
- `rescuevision_ai.v4.artifacts`: atomic JSON, SHA-256 validation, complete-file manifests and resume compatibility checks.
- `rescuevision_ai.v4.data_audit`: `audit_dataset(root, adapter, out_dir)` for an xBD-shaped raw tree.
- `rescuevision_ai.v4.datasets`: `load_manifest` and `PairedDataset` with separate localization and damage validity masks.
- `rescuevision_ai.v4.evaluation`: `OfficialAccumulator` for the external `0..4` encoding. Internal `255` ignore values must be resolved before scoring.
- `rescuevision_ai.v4.models.distillation`: frozen-teacher wrapper, trainable feature projection, normalized valid-patch loss and cache identity for the DINOv3 7B teacher branch.
- `rescuevision_ai.v4.models.post_only`: five-class post-event typology label map, independent macro-F1 and footprint-conditioned classification head.
- `rescuevision_ai.v4.models.defects`: explicit absent/negative/positive annotation handling, overlapping dense masks and independent sigmoid channels.
- `rescuevision_ai.v4.task_adapters`: grouped structure/photo split-integrity checks shared by specialist datasets.
- `rescuevision_ai.v4.specialist_datasets`: strict post-only and defect JSONL adapters that preserve annotation-unit, footprint-source and missing-label provenance.
- `rescuevision_ai.v4.bundle`: self-contained checkpoint hash, preprocessing identity, label-map/recipe metadata and deterministic reference-prediction digest.

The Kaggle notebooks under `ai/kaggle/building-damage/v4/` are intentionally thin
wrappers. They read environment-provided immutable inputs and call the V4
package; they do not clone moving branches, install hidden dependencies,
submit jobs, tune thresholds or print credentials.

`scripts/v4_submit_spec.py` marks every request as `kaggle_remote` and
`local_execution_allowed: false`; generating or reviewing a request does not
launch it.

All acquired sources are tracked in `configs/v4/dataset_registry.yaml`. They
are combined through task-specific adapters and validity masks according to
`ai/kaggle/building-damage/v4/notes/v4_all_dataset_training_policy.md`; incompatible labels are never merged
into one target.

The 7B configuration is a profile-only contract. It deliberately does not
download or invoke the gated Hugging Face checkpoint. A real run must first

authorized Kaggle/Colab GPU, then record the resulting artifact manifest.

The V4 namespace is intentionally separate from the removed legacy package imports
used by the API and old scripts. No API predictor was replaced or silently repaired.
