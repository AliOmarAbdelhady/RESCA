# RESCA development rules for the single-server demo

Research draft, 25 November 2026. These are proposed merge and promotion criteria. No gate implementation, server benchmark, model qualification or operational certification is implied. Numerical limits below are starting budgets selected for this project. Record hardware, fixture size and baseline before adopting them.

Follow the [owner decisions](decisions-log.md), [doc outline](doc-set-outline.md), [database security model](../../database/README.md), [frontend boundaries](../../frontend/README.md), [system design](../documentation/chapter5/section_3_3.md) and [review record](../team-plan/review/README.md). Older frontend plans mention WebSockets. The approved read stream is SSE; clients submit commands over authenticated HTTP. The decisions log labels the Postgres queue/outbox, SeaweedFS, dbmate, protected trunk, Compose/Caddy and SOPS/age as consensus defaults awaiting confirmation. Rules below specify their acceptance criteria if adopted.

Each gate name maps to a proposed command in the gate list. A dash in the exception column means no exception. Any other exception must be path- and rule-specific, have an owner, reason, compensating test and expiry, and receive human approval. A gate must detect a deliberately invalid fixture before it can become required. Review-only judgments require a named human in the PR.

| X3 | Emit structured logs with operation, duration, outcome and opaque request/job/trace IDs propagated across outbox and worker. | Free text leaks identities and breaks incident reconstruction. | Privacy: inject sentinel credentials, coordinates, media URLs and names, then scan logs, spans and crash events; verify one linked trace. ## 2. FastAPI backend

| ID | Rule | Failure prevented | Required evidence / gate | Exception | Source |
|---|---|---|---|---|---|
| B1 | Keep domain routers thin, services responsible for transactions and repositories responsible for parameterized SQLAlchemy queries. | Cross-domain writes bypass invariants. | Static: import-linter layers and forbidden contracts; AST rejects repository commits, raw SQL interpolation and routers importing sessions. | Reviewed parameterized spatial SQL inside repositories. | [Reference](https://import-linter.readthedocs.io/en/stable/contract_types/layers/) |
| B2 | Version public paths under /api/v1; use separate typed input/output models, bounded fields and allowlisted filters/sorts. | Overposting and unbounded queries expose data or exhaust CPU. | Contract: use Pydantic strict validation on JSON bodies and reject unknown input fields with extra='forbid', invalid ranges and unauthorised writable fields; snapshot output fields and operation IDs. | Wire query strings use explicit documented parsing; additive optional response fields allowed. | [Reference](https://fastapi.tiangolo.com/tutorial/response-model/) |
| B3 | Paginate mutable lists with opaque scope-bound cursors, stable ordering plus unique tie-breaker, default 25 and max 100. | Busy incidents otherwise skip or duplicate records or return entire tables. | API: test equal timestamps, changed filters, invalid cursors, last page and inserts between pages; document snapshot semantics. | Small fixed reference enums may be returned whole. | [Reference](https://google.aip.dev/158) |
| B4 | Derive identity from verified credentials; authorize action, incident membership, object and writable properties on every operation. | A valid responder might read another agency’s case or invoke commander actions. | Auth: verify issuer, audience, allowed signature algorithm, expiry and current account status; enumerate OpenAPI operations, roles and object states; require allowed and denied fixtures, suspended user, expired credential, foreign agency/citizen and restricted-field cases; assert unchanged state on denial. | Named public/health paths still declare policy and safe response fields. | [Reference](https://owasp.org/API-Security/editions/2023/en/0x11-t10/) |
| B5 | Bind retryable command keys to principal, operation and request hash; atomically persist result with the effect. | A lost SOS acknowledgment can create two incidents. | API: submit concurrently, replay after timeout, reject changed payload with 409, prevent cross-user lookup; key retention covers the offline replay horizon. | Naturally idempotent operations with a tested unique business key. | [Reference](https://google.aip.dev/155) |
| B6 | Bound request bytes, per-account and trusted-source request rates, active streams, queue depth and expensive work separately. | One upload or reconnect loop can starve responders. | Load: exhaust each quota, verify 429 plus Retry-After or 503 for saturation, keep reserved SOS capacity, show unsent state. Trust proxy addresses only from Caddy. | Separate measured quotas for approved batch work. | [Reference](https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/) |
| B7 | Quarantine uploads privately; check declared and decoded type, dimensions, expanded bytes, duration and ownership before promotion. | Malformed imagery can exhaust memory or expose citizen photos. | API: fixtures for mismatched types, oversize decoded image, interrupted upload and foreign download; generated object keys, authenticated retrieval and orphan cleanup. | Reviewed file-type-specific limits for large rasters. | [Reference](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) |
| B8 | Open one transaction per unit of work and set transaction-local identity from the authenticated principal before accessing protected rows. | A pooled connection can inherit the preceding citizen’s identity. | DB: reuse one connection as A then B after both commit and rollback, including missing identity; ensure no owner/BYPASSRLS login and no shared concurrent AsyncSession. | Privileged migrations use separate credentials. | [Reference](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html) |
| B9 | Budget SQL round trips per route and load relationships explicitly. | An incident list can issue one query per responder. | API: count before_cursor_execute on 1 vs 25 parents, require constant count and declared ceiling (initial list ceiling 6); use raiseload in tests. | Explicit bounded batch query count documented per route. | [Reference](https://docs.sqlalchemy.org/en/20/orm/queryguide/relationships.html) |
| B10 | Bound downstream time, retry only transient idempotent work with jitter at one layer and open a circuit after repeated failure. | Slow inference can stall dispatch or multiply requests. | Jobs: fake clock and unavailable worker; enforce connect/read/total deadline, max two retries within remaining budget, open/half-open probe, report AI unavailable while core API stays ready. | Long-running inference uses async jobs with separate deadline. | [Reference](https://sre.google/sre-book/addressing-cascading-failures/) |
| B11 | Write business state and outbox in one transaction; claim jobs with bounded leases, recover on crash and deduplicate effects. | A crash can lose a submitted job or publish it twice. | Jobs: terminate before/after commit, lease expiry and external write; assert eventual completion once per logical key, max attempts and visible terminal failure. One heavy slot across all workers. | Read-only synchronous operations. | [Reference](https://microservices.io/patterns/data/transactional-outbox.html) |
| B12 | Serve incident-scoped SSE from a durable commit-ordered cursor; reauthorize during streaming and resume after disconnect. | Revoked users can retain a feed or miss an earlier transaction that committed late. | Events: overlap commits, reconnect with Last-Event-ID, replay duplicates, revoke membership, trim history and force full resync; verify heartbeat, bounded buffers and proxy flush. | Ephemeral heartbeats carry no domain state. | [Reference](https://html.spec.whatwg.org/multipage/server-sent-events.html) |
| B13 | Set endpoint status semantics and reserve response time for interactive traffic during inference. | A 200 acknowledgment can conceal pending work or severe CPU contention. | API/Load: verify 201 creation, 202 queued with status URL, 401 invalid identity, 403 forbidden or uniform 404 for hidden objects, 422 bad input; under one heavy job target p95 reads <500 ms and SOS durable acceptance <1 s. | Bulk results use a documented asynchronous budget. | [Reference](https://www.rfc-editor.org/rfc/rfc9110) |
| B14 | Apply TLS, explicit CORS origins, nosniff, restrictive frame policy and no-store on sensitive responses at the public edge. | Cross-origin requests or browser caches expose case data. | Edge: inspect Caddy responses including 4xx, preflight denied origin, cookie flags and CSP on HTML; enable HSTS on HTTPS deployment. | Loopback development with isolated credentials. | [Reference](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html) |

### Implementation details for the first gates

- **Cursor correctness (B12).** A PostgreSQL sequence can allocate two IDs in one order and commit them in the opposite order. A reader that saves the larger ID could miss the later commit. Serialize cursor allocation and event insertion on a per-incident counter row inside the business transaction, or use a publisher with equivalent ordering evidence. Page by that cursor, authenticate the incident separately, and return an explicit resync response for a cursor outside retention. [PostgreSQL sequence behavior](https://www.postgresql.org/docs/18/functions-sequence.html).
- **Baseline security matrix (B4, D2).** Start with staff in two agencies, an invited agency, a suspended user, two citizens, the pipeline worker and a readonly login. Test each accessible view as its caller, direct child-partition access, and service-role membership. Verify that schema owners alone can create objects in a definer function’s search path. Fail if a new route, table or grant lacks an expectation. [RESCA baseline](../../database/schema/15_security.sql).
- **Guard integrity (G2–3).** Evaluate protected-path diffs outside PR-controlled code. Include the gate runner, every executable dependency it imports, the workflow selection map and its own tests in the protected set. Give untrusted builds disposable credentials. Never use Git author text as proof of owner identity. Git cannot prove who typed a line; enforce owner-controlled submission and require a human authorship declaration. Where repository plan or visibility prevents branch protection, restrict write access to the owner and have the owner merge only the exact tested SHA after independently verifying CI. [GitHub branch protection](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches).
- **Real configurations.** Bind ESLint to the actual TS projects and pin the strict configuration version. Set import-linter's `type = layers` within domains and `type = forbidden` for cross-domain private imports. Pydantic's extra-field policy and strict coercion address different failures and need independent fixtures. [TypeScript configurations](https://typescript-eslint.io/users/configs/), [forbidden imports](https://import-linter.readthedocs.io/en/stable/contract_types/forbidden/), [Pydantic configuration](https://docs.pydantic.dev/latest/api/config/).
